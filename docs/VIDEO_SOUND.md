# NO PEEKING! Video Sound (Sound Designer & Mixer)

Everything here is generated by scripts in `tools/video/audio/`, and every number below comes from a script run on the files themselves. Outputs live in `videos/audio2/`.
Chromium renders (library, design `exact` renders, score, beds, mixes with Qubblese voices) run through `tools/video/safe-run.sh --heavy -- …`, which takes one of 3 render slots machine-wide; pure-python jobs run through `safe-run.sh -- …` (see docs/VIDEO_RESOURCES.md).

## 1. Hi-fi game SFX library (`build_library.py` → `videos/audio2/lib/`)
Each sound is rendered offline by the game's own engine (`src/audio`) in headless Chromium (`render.js` + `engine_render.py`), at 48 kHz float, then written as **48 kHz / 24-bit** WAV with TPDF dither. The live master chain (glue compressor, limiter, trim) is bypassed, and `Math.random` is seeded, so the renders are deterministic.

| Folder | Content | Count |
|---|---|---|
| `game/` | all **25 SfxName**, dry (no engine reverb), 3 seeded variants each (the mixer rotates them, the way the game varies) | 75 |
| `game_wet/` | the same, with the game's own convolution reverb (as heard in-game) | 25 |
| `bots/` | `botNote` for bots a–h × BEEP/QUIET (a = marimba F3 "DUM", b = bell C6 "ding-ding"; the videos use a/b) | 16 |
| `chords/` | `syndromeChord` for every 2-, 3- and 4-bot syndrome | 28 |
| `voices/<who>/` + `voices/index.json` | Qubblese for **every dialogue line in the game**, typed at the game's 22 ms/char rate: Schrödi 55, Flipper 18, Phasey 7, Wobbles 3, Qubble 2, Eye 2 | 87 |
| `trailer/` | **trailer-weight** featured SFX: transient shaping (+3…+8 dB attack), a 2–4 kHz presence lift (+2…+4 dB at 2.8 kHz, Q 0.9), a 40–60 Hz sub thump tuned per sound, and a 0.7 s room. Each is normalised to −16 LUFS max-momentary at ≤ −1 dBTP | 29 |
| `exact/` | exact-pitch renders (game synthesis called directly, without the ±3 % random pitch): the tuned BEEPs and `level_win` in C and F | 4 |

The relative levels are the engine's own balance (`SFX_GAIN`). One global gain (+2.0 dB) puts the loudest SFX at −1 dBFS. Every file starts at the engine call time, so the engine's 5 ms scheduling lead is kept and placement is frame-exact. The manifest (`library.json`) lists duration, sample/true peak and max momentary loudness for each file. Listen-proxy: `reports/lib_game_vs_trailer.png`.

## 4. The mixer: `tools/video/audio/mix.py`
```bash
tools/video/safe-run.sh --mem 5G -- python3 tools/video/audio/mix.py tools/video/edl/trailer.edl.json \
    [--music videos/audio2/score_alt/score_alt.wav]   # public cut (default bed: the EDL's audio.music, else the song)
    [--preset trailer|mechanic|showcase] [--cues extra.json ...] [--no-design] [--out DIR]
    [--target -14] [--tp -1.0] [--margin 6] [--no-engine]
```
If the EDL has Qubblese voices (mechanic and showcase), add `--heavy` to the safe-run call, because the voices are rendered by the engine in Chromium. Drop `--mem 5G` from the example if you like: the shared pool no longer needs per-job caps.
It reads the Editor's np-edl/1 EDL via `tools/video/edl/edl.py`. Outputs go to the EDL's `audio.mix` / `audio.mixreport` / `audio.stems` paths, or to `--out`:
`mix.wav` (24-bit), `stems/{music,sfx,voices,design}.wav` (post-gain, pre-limiter, so they sum to the mix), `mixreport.json`, `cues.json` (timeline cue list for the A/V gate) and `mix.png`.

1. **Frame-exact game SFX.** Every capture event (`sfx`, `botNote`, `syndromeChord`, `voice`) with a non-null `frame` inside a clip's [in, out) is placed at the first timeline frame that shows that source frame. This uses the Editor's own frame map, so constant speeds and ramps are honoured. The start sample is `frame × 800`. A source frame that is skipped by a speed-up maps to the next shown frame. `frame: null` means off camera or pre-roll; those events are skipped and listed.
2. **Speed thinning.** At > 1.05× speed: the same name needs a minimum gap of 90 ms × (1 + log2 speed); density is capped at 3/2/1 events per 250 ms (below 2× / below 4× / 4× and up), with higher priority winning (peek, win, flip, bots first; UI last); UI clicks, hovers and card sounds are dropped at ≥ 2×; surviving non-featured sounds lose 1.5 dB per doubling; voices are muted above 1.3×. The engine's own 30 ms anti-spam always applies. **Every dropped event is listed** in `mixreport.thinned` (the inverse-SFX gate).
3. **Voices.** Lines are rebuilt from the logged characters (lines cut off by the capture end are completed from the game's line library). Every voice call is then rendered through the game's Babbler at its timeline time, in one offline pass, so the in-game throttle and the per-speaker voices are exact. If Chromium is unavailable, the pre-rendered line library is used instead.
4. **Designed layers.** The cue list (`cues/trailer_design.json`, anchored to the sheet), plus the EDL's clip cues (the Editor's names are aliased: `peek_collapse_impact`, `title_letters_pitched`, `bot_beep_dry`, `drop_impact`, `snap`, `silence`; the EDL wins on a group), plus automatic transition sweeteners (shatter, glitch). `zone:sfx_gain` gives the proof SFX +3 dB, so they carry the submerged section. `only_with` picks bed-specific layers.
5. **Ducking = 2–5 kHz dynamic EQ.** Every featured SFX/voice gets a **−6 dB dip of the music's 2–5 kHz band** (10 ms look-ahead + 10 ms attack, held for the cue's body, ~150 ms release). Non-featured SFX get −3 dB. The band split is zero-phase, so music = rest + band exactly. A solver then measures each featured cue: its max momentary loudness (400 ms) against the ducked music in the same window. A cue short of margin + 1 LU first gets a deeper band dip (≤ 12 dB). Only after that does it get a broadband dip (≤ 12 dB), then a cue boost (≤ +6 dB). The report shows `band_dip_db`, `fallback_broadband_db`, `boost_db`, the LU margin and the 2–5 kHz band margin per cue.
6. **Peak-to-loudness control.** Featured cues are limited to a PLR of ≤ 10 dB (trailer) or ≤ 14 dB (game presets) before placement. Without this, the trailer SFX (PLR ~15 dB) drove the bus to +10 dBFS, and the master limiter crushed them.
7. **Master.** The bus is gained to −14 LUFS, then a true-peak look-ahead limiter (4× oversampled detector) at a −1.2 dBTP ceiling; the gain is iterated to ±0.15 LU. The result is verified with the in-house BS.1770-4 meter and **ffmpeg ebur128**.
8. **Report** (`mixreport.json`): every cue (id, kind, name, stem, frame, sample, source clip/src_frame/speed, gains, dips, cue vs music LUFS-M, margin, pass), the thinned and off-camera events, music gates, and the loudness results (own + ffmpeg, pass flags). It also includes the Critic's **loudness-curve gate** (build rises; drop ≥ build avg + 6 / peak + 4; payoff ≥ montage + 2; proof ≥ 6 under montage) on the bed, on the ducked music stem and on the full mix, and the Director's **proof-energy check** (max short-term LUFS of the mix over the proof section, target ≈ −14, pass −16…−12).

Presets: `trailer` (music −20 LUFS pre-master, trailer-weight SFX +4 dB, no voices, design list), `mechanic`/`showcase` (music −27/−25 LUFS, game SFX at engine balance, Qubblese voices on and featured at −2/−3 dB, no design list). Designed sounds can replace the in-game sound at their moment (`suppress_game`): `beep_tuned_C5` replaces the botNote/listen_beep within 0.5 s of f1362, and `level_win_big` replaces the in-game level_win at f3026. Each replacement is logged in `thinned`.

### Score segments in `mix.py` (`--score PLAN`, the EDL's `audio.score`, or the preset plan `cues/trailer_score.json`)
- **Sources:** `song`, `public`, `groove_*` (or any path). Every source gets the bed's normalisation gain, so relative levels hold.
- **Segment fields:** `{source, from, to | clips: "programming" (+ section, within), mode: layer|replace, gain_db, bed_db, xfade_frames}`.
- **Downbeats:** entries and exits snap to cue-sheet downbeats. The equal-power fade-in **completes on** the entry downbeat; the fade-out **starts on** the exit downbeat.
- **Modes:** `replace` crossfades the bed out under the segment. `bed_db` dips the bed under a layer.
- **Programming runs use a bar-majority rule.** A bar (downbeat to downbeat) carries the groove when ≥ 50 % of its frames show programming clips. The 32- and 64-frame hemiola/beat cuts can't each land on a downbeat, so this is the honest compromise. A clip counts as programming if it has a `programming` flag, `audio.programming`, section `proof`, or a matching shot name (`pg_*`, editor, card guide, test strip, QoL, snippets, step mode, export…). The Lab Notebook circuit is a world cut.
- **Reporting:** every segment is written to `mixreport.score_segments` with its requested/snapped frames, `on_downbeat`, gains, crossfade and bar coverage.

**Default plan:**
- `groove_perc` −12 dB with the bed −0.8 dB under it, plus `groove_type` −10 dB, under the proof split screen (f1586–2162). The bed dip keeps the proof section's energy unchanged, so the gate is unaffected.
- `groove_light` −4 dB under the programming bars of the montage.

**Alternative** (`cues/trailer_score_replace.json`): the same, but `groove_full` **replaces** the bed for the montage's last two bars (f2642–2834, the beat cuts), and the bed returns on the Lights Out downbeat.

## 11. Music-first trailer mix (after the user's "the audio mixing is all over the place")
**Diagnosis of the 21:30 mix** (from `analyze_mix.py`): it was SFX-first. Every mixing rule pushed effects UP and nothing capped them: a per-cue "≥ 6 LU over the music" floor, a −16 LUFS-M proof floor, a +2–4 dB presence lift *and* 2–5 kHz ducking of the music. The energy curve followed SFX density, not the music.

**The trailer preset is now `music_first`** (`tools/video/audio/mixfirst.py`, wired into `mix.py`; mechanic and showcase keep the ducking path).

1. **Music automation.** The bed (song or public score, plus the groove segments) is ridden to per-section targets, measured exactly as `analyze_mix.py` measures: centred 3 s short-term, and for sections under 3.5 s the interior momentary median.
   - Targets: cold_open −24 · peek −21 (ride) · build −22→−17 bar by bar · drop −8.5 · proof −15 · montage −12 · Lights Out −20 · payoff −8.5 · closing music box −22 (ride) · snap −13 · end card −15→−26.
   - Momentary ceilings on the music before the drop: build −13.5, peek −14, cold_open −16. The song's own pre-drop riser can no longer out-shout the drop.
   - Boundary ramps are ≥ 200 ms raised-cosine: rising ramps finish ON the downbeat, falling ramps start ON it.
   - Polish: 0.5 s fade-in from black; a narrow, mono-safe reverb fill in the sparse sections (cold open, Lights Out pocket, closing music box); a gentle 2:1 on the cold-open music; a 4 s end fade.
   - The whole stage runs 6 dB under its post-master targets for float headroom.
2. **SFX windows instead of floors.** Each window is measured against the music's momentary level at the cue's own loudest 400 ms.

   | Cue type | Window (LU over the music) | Aim |
   |---|---|---|
   | Featured hits | +3 to +7 | +5 |
   | Hits before the silence | +3 to +7 | +3.5 |
   | Proof cues | +3 to +5 | +4 |
   | Drop co-hit (no ducking under the logo reveal) | 0 to +4 | +1.5 |
   | Hits ON the song's payoff / final chord | 0 to +4 | +2.5 |
   | Pitched title letters ("phrase") | 0 to +3 | +1 |
   | Card accents | −6 to +4 | 0 |
   | Lights Out pocket (SFX at most equal to the music) | −3 to +2 | −1 |
   | QUIET answer | 4.5 LU under its BEEP | — |
   | Non-featured cues | 8 dB under | — |
   | Risers | peak 8 dB under | — |
   | Beds | integrated 8 dB under (per-cue `under_db`) | — |
   | Hits in true silence | absolute level | — |

   - Room tone stays at −60 dBFS.
   - Cues within 3 frames are levelled as one group; beds are levelled on their own.
   - After the SFX bus, every group is re-measured and corrected (≤ 8 passes, correction capped at ±15 dB for featured groups and ±9 dB otherwise).
   - Every tail fades over ≥ 20 ms; sig_a's tail is cropped at 2.2 s.
3. **Tone.** The small presence lift on the trailer SFX stays; the music band-dip is gone, so there's no double emphasis. A per-section presence match (mono, the analyzer's metric) cuts the SFX's 2–5 kHz where SFX − music would exceed +4.5 dB: build −1.9 dB, proof −1.4 dB, Lights Out −2.1 dB.
4. **SFX/design bus.** 3:1 compression (10/120 ms), 2 dB GR at the bus's p95 level (max 4 dB), then a transient limit at p99.5 + 4 dB.
5. **Master.** 2:1 glue (30/150 ms; 1.56 dB mean GR in the loud sections), then the true-peak limiter at **−2.0 dBTP** (the −1.5 target minus 0.5 dB of codec headroom), with integrated loudness iterated to −14. Every mix is re-encoded to AAC 320k and re-measured (`aac_check`).
6. **Phone simulation.** `videos/final/review/trailer_phone_sim.wav`: mono, HPF 250 Hz, LPF 7 kHz, a +5 dB resonance at 1.1 kHz, light saturation, played about 4 dB down.

**QA gate `mix_analysis`** (`tools/video/audio/mix_gates.py <workdir>`, which runs `analyze_mix.py` and writes `<work>/mix_gates.json`):
- the anticipation rules, plus the drop is the peak;
- the music is the dominant stem (SFX may equal it in proof and Lights Out);
- the silences are ≤ −35;
- in-section spread ≤ 12 LU (designed fades exempt);
- ≤ 3 spikes and ≤ 5 off-mark jumps;
- 2–5 kHz SFX − music ≤ +6 dB;
- integrated −14 ±0.5;
- true peak ≤ −1.5 dBTP on the encoded AAC.

**Measurement fixes in `analyze_mix.py`** (marked in the source):
- **Short sections.** Sections under 3.5 s use the interior momentary median. A centred 3 s window over a 1.6 s silence reads its neighbours: the silences measured −15 even when empty.
- **Jump tolerance.** The jump-to-mark tolerance is 20 frames (12 for the 400 ms window's half-width + 6 for the 200 ms difference + 2). Every designed step at a cut used to count as an off-mark jump.
- **Double gain.** Stems written by `mix.py` already include the master gain (`stems_scaled_by_master_gain`). The analyzer scaled them a second time, inflating every per-stem level by the master gain (about +5 dB), the 21:30 diagnosis included. Relative comparisons were unaffected.

It all re-runs on any EDL change: `mix.py <edl>` → `mix_gates.py <workdir>`.

**Build rises bar by bar on the full mix** (Critic polish, fix 5): `mixfirst.monotonic_build`. After the SFX are placed, the build's per-bar RMS of the whole pre-master mix (music_gate's metric) is measured. Any bar quieter than the one before it gets a music lift with 200 ms raised-cosine ramps that complete on its downbeat. A peak guard then pulls the lift back wherever it would raise the build's momentary peak, so the drop stays the peak.
